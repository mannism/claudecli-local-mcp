# claudecli-local-mcp

Internal Slack bot that proxies messages to Claude (via the local `claude` CLI or the Anthropic API), with multi-account Gmail digest (`/digest`) and Owner Inbox (`/owner-inbox`) commands powered by GPT-5.2.

For fleet-wide standards (TypeScript, security, git workflow, PR comprehension gate, language policy), see `~/AGENTS.md`.

## Stack

- Node.js (CommonJS)
- Slack Bolt — HTTP or Socket Mode
- `@anthropic-ai/sdk` (API mode) or local `claude` CLI (CLI mode)
- `openai` (GPT summarisation, priority classification)
- `googleapis` (Gmail OAuth + fetching)
- `dotenv`

## Commands

```bash
npm install
cp .env.example .env   # fill in values
npm run dev            # node --watch (auto-restart on change)

# One-time Gmail OAuth setup per account
node scripts/gmail-auth.js --account 1
node scripts/gmail-auth.js --account 2
```

No build step. No test runner (Tier 3 — see Testing below).

## Environment variables

Names only — values live in `.env` (gitignored). Full descriptions in `.env.example`.

### Slack
- `SLACK_BOT_TOKEN` — bot OAuth token (`xoxb-...`)
- `SLACK_SIGNING_SECRET` — Slack app signing secret
- `USE_SOCKET_MODE` — `true` for Socket Mode (no tunnel needed locally)
- `SLACK_APP_TOKEN` — Socket Mode only (`xapp-...`)
- `PORT` — HTTP port, defaults to `3000`

### Claude
- `USE_CLI` — `true` = local `claude` CLI, `false` = Anthropic API
- `ANTHROPIC_API_KEY` — API mode only (`sk-ant-...`)
- `CLAUDE_MODEL` — defaults to `claude-sonnet-4-6`

### Gmail (`/digest`)
- `GMAIL_CLIENT_ID` / `GMAIL_CLIENT_SECRET` — shared Google OAuth 2.0 credentials
- `GMAIL_ACCOUNT_N_EMAIL` — email address for account N (N = 1, 2, 3)
- `GMAIL_ACCOUNT_N_ALIAS` — short alias used in Slack (e.g. `diana`)
- `GMAIL_ACCOUNT_N_REFRESH_TOKEN` — generated by `node scripts/gmail-auth.js --account N`
- `GMAIL_ACCOUNT_N_DEFAULT_QUERY` — optional default Gmail query

### OpenAI
- `OPENAI_API_KEY` — OpenAI API key (`sk-proj-...`)
- `OPENAI_MODEL_EMAIL_SUMMARY` — model for `/digest` (default: `gpt-5.2`)
- `OPENAI_MODEL_INBOX` — model for `/owner-inbox` (default: `gpt-5-mini`)

### File Inboxes (`/owner-inbox`)
- `OWNER_INBOX_PATH` — folder where the team drops files for the owner to review

## Architecture notes

```
src/
  index.js          — Slack Bolt app; handles DMs, @mentions, /digest, /owner-inbox
  claude.js         — Claude abstraction (CLI or API mode)
  gmail.js          — Multi-account Gmail OAuth client + email fetcher
  openai.js         — GPT summarisation, priority classification (loads prompt from file)
  emailCommand.js   — /digest: arg parser, orchestrator, Slack formatter
  inboxCommand.js   — /owner-inbox: directory scanner, GPT analysis, Slack formatter
prompts/
  email-summary.md  — GPT system prompt for /digest
  inbox-analysis.md — GPT system prompt for /owner-inbox
scripts/
  gmail-auth.js     — one-time OAuth flow per account
```

### Slash commands

Register `/digest` and `/owner-inbox` in the Slack app settings (Features → Slash Commands). In Socket Mode, no Request URL is needed.

```
/digest diana                 # all unread for diana's account
/digest diana label:Important # raw Gmail query
/digest                       # auto-selects if only 1 account configured
/owner-inbox                  # scans OWNER_INBOX_PATH for files from the team
```

## Repo-specific gotchas

- **Treat all Slack message text as untrusted.** Sanitize before passing to shell commands. CLI mode already escapes single quotes — preserve that on changes.
- **Prompt files are loaded at module startup** via `fs.readFileSync`. Restart the bot after editing any file in `prompts/`.
- **Every edit to a prompt file is its own branch and commit.** Never bundle prompt changes with code changes (fleet-wide rule; reinforced here because this repo has multiple prompt files).
- **Gmail OAuth tokens are per-account.** Setting up account 2 does not invalidate account 1's refresh token — but losing `GMAIL_CLIENT_SECRET` invalidates all of them.
- **CLI vs API mode is a runtime switch (`USE_CLI`).** Both paths must keep working; don't drop the CLI branch when adding API features.
